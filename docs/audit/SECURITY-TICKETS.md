# Daftar Tiket Remediasi Audit Keamanan Proto (S1 - S18)

> Status remediasi per 2026-10-16: ✅ = sudah diperbaiki, 🟡 = diperbaiki sebagian, ❌ = tidak valid, ⚪ = risiko diterima; verifikasi lengkap di [AUDIT-VERIFICATION.md](./AUDIT-VERIFICATION.md).

Dokumen ini merangkum seluruh tiket remediasi keamanan berdasarkan temuan audit pada `docs/audit/SECURITY-AUDIT.md`.

## Tabel Tiket Remediasi Keamanan

| ID                | Status / Severity | Bug                                                                                                                                              | Resolve                                                                                                                                                                                                                 | Reason                                                                                                                                                                                                                                                                                                                                                         |

| **S1**            | High (Critical)   | Inverted SqrtPriceX96 pada Inisialisasi Pool Uniswap V4 (`CurveMath.computeSqrtPriceX96` / `BondingCurve._prepareGraduationV4`)                  | Balik pembagian rasio cadangan menjadi `sqrt(tokenReserve) * 2^96 / sqrt(ethReserve)` dan lakukan bit-shift sebelum akar kuadrat untuk mencegah pemotongan presisi.                                                     | `CurveMath.computeSqrtPriceX96` membagi `sqrt(ethReserve)` dengan `sqrt(tokenReserve)`, terbalik dari konvensi harga Uniswap V4 (`currency1 / currency0`). Akibatnya harga terdistorsi sebesar faktor ~4.86e7x, memungkinkan arbitrase langsung menguras 100% dari 4.2 ETH likuiditas graduasi.                                                                |
| **S2** ✅         | High (Critical)   | Pengurasan Saldo Global Native ETH & Protocol Fee Dibuang di Locker V4 (`ProtoLiquidityLockerV4.claimFees`)                                      | Terapkan pemisahan akuntansi saldo fee per token (`tokenEthFees[token]`), koleksi fee per posisi NFT Uniswap V4, transfer langsung `protocolFee` ke `protocolFeeRecipient`, dan kurangi saldo fee terakumulasi.         | `claimFees` membaca `address(this).balance` global tanpa pemisahan per token dan mengabaikan nilai kembalian `protocolFee` dari `calculateLockerSplit`. Deployer token mana pun dapat memanggil fungsi ini berulang kali dalam loop untuk menyedot 100% ETH milik token lain dan fee protokol.                                                                 |
| **S3** ✅         | High (Critical)   | Default Snapshot Nol Menghanguskan Hak Dividen Pemegang Token (`HolderFeeDistributor.earned`)                                                    | Inisialisasi `snapshotBalance` ke saldo live saat pertama kali klaim/interaksi (`snap == 0 ? liveBalance : calculateEffectiveBalance(snap, liveBalance)`), atau pasang hook checkpoint otomatis pada transfer token.    | `earned()` menghitung dividen berdasarkan `min(snapshotBalance, liveBalance)`. Karena token tidak otomatis memicu checkpoint pada transfer, pemegang baru memiliki `snapshotBalance = 0`. Klaim dividen pertama mengevaluasi fee ke 0 sambil memajukan tracker `userRewardPerTokenPaid` ke akumulator terbaru, mengunci WETH permanen di kontrak.              |
| **S4** ✅         | High              | Ketiadaan `receive()` pada Factory V2 Menggagalkan Peluncuran Token (`LaunchpadV2Factory.launchTokenV2` / `LaunchpadV2FactoryArc.launchTokenV2`) | Tambahkan `receive() external payable {}` pada `LaunchpadV2Factory` dan `LaunchpadV2FactoryArc`, atau ubah `BondingCurve.buyFor` agar mengirimkan `refundEth` langsung ke parameter `recipient`.                        | Saat pembelian awal kreator (`initialBuyEth`) mencapai target kurva, `BondingCurve.buyFor` menghitung kelebihan ETH dan mengirimkannya ke `msg.sender` (alamat kontrak factory). Karena factory tidak memiliki fungsi payable `receive()`, panggilan transfer gagal dan seluruh peluncuran token revert.                                                       |
| **S5** ❌ INVALID | High              | Pajak Penjualan Token Menguras Cadangan Kurva & Mengunci Dana Permanen (`BondingCurve.sell` & `emergencyWithdraw`)                               | Izinkan `emergencyWithdraw` dipanggil jika kurva belum lulus graduasi setelah batas waktu (`launchTime + MIGRATION_DEADLINE`), atau jangan kenakan pajak penjualan pada token yang ditransfer kembali ke kurva bonding. | Setiap penjualan token memotong `sellTaxBps` dan mengirimkannya ke `taxRecipient`, mengurangi saldo fisik token kurva di bawah batas cadangan pool sebelum `totalEthRaised` mencapai `graduationTarget`. Seluruh pembelian selanjutnya revert dengan `InvalidAmount()`, dan dana terkunci selamanya karena `emergencyWithdraw` mewajibkan `graduated == true`. |
| **S6**            | High              | Inisialisasi Likuiditas Single-Sided Uniswap V3 Full-Range Selalu Revert (`LaunchpadFactory.launchToken`)                                        | Tentukan rentang tick likuiditas satu sisi (`tickLower >= currentTick` untuk token0) yang berada di luar harga aktif saat inisialisasi, alih-alih menggunakan rentang penuh `[-887200, 887200]`.                        | `launchToken` menginisialisasi pool Uniswap V3 pada tick ~ -207242 dan meminta pencetakan posisi full-range dengan 0 WETH. Uniswap V3 mewajibkan kedua aset jika rentang mencakup tick aktif; suplai 0 WETH menghasilkan likuiditas 0 sehingga `positionManager.mint` revert pada pemeriksaan slippage.                                                        |
| **S7**            | High              | Pembulatan Bawah Pengurangan Fee Menahan Total Dana di Bawah Target Graduasi (`BondingCurve.buyFor`)                                             | Tambahkan kondisi graduasi alternatif: `shouldGraduate = (totalEthRaised >= graduationTarget                                                                                                                            |                                                                                                                                                                                                                                                                                                                                                                | grossTokensOut == curveAvailable);` agar kurva otomatis lulus saat seluruh suplai kurva habis terjual. | Saat sisa token kurva dibeli penuh, pembulatan bawah pada platform fee menyebabkan `netEth` berkurang beberapa wei dari nilai yang dibutuhkan untuk mencapai target graduasi. Karena suplai kurva telah habis, pembelian lanjutan revert dengan `InvalidAmount()` dan kurva membeku tanpa bisa graduasi. |
| **S8** ✅         | Medium            | Slot Squatting 1 Wei Memblokir Jadwal Vesting Penerima (`VestingVault.createVestingSchedule`)                                                    | Ubah mapping penyimpanan menjadi `mapping(address => mapping(address => mapping(address => Schedule)))` (token => creator => beneficiary => Schedule) atau gunakan ID jadwal unik.                                      | `createVestingSchedule` tidak memiliki pembatasan akses dan memetakan jadwal hanya berdasarkan `[token][beneficiary]`. Penyerang dapat membuat jadwal 1 wei selama 100 tahun untuk alamat target, menyebabkan upaya alokasi resmi dari tim/protokol selalu revert dengan `ScheduleExists()`.                                                                   |
| **S9**            | Medium            | Imutabilitas `setLiquidityPool` Mematikan Pajak Kreator Pasca-Graduasi di DEX (`LaunchpadToken.setLiquidityPool`)                                | Hapus pengecekan `if (liquidityPool != address(0)) revert PoolAlreadySet();` khusus untuk pemanggilan oleh factory terotorisasi, atau gunakan pemetaan whitelist pool DEX.                                              | `setLiquidityPool` hanya dapat dipanggil satu kali dan terkunci ke alamat bonding curve awal. Setelah kurva lulus dan likuiditas dipindahkan ke Uniswap V3/V4, perdagangan terjadi di pool DEX yang tidak dikenali sebagai `liquidityPool`, sehingga pajak jual/beli kreator tidak pernah dipungut.                                                            |
| **S10** ✅        | Medium            | `ProtoMemeHook` Mengabaikan `buybackShareBps` & `pendingEthFees` Tidak Pernah Terisi (`ProtoMemeHook.sweepPoolFees`)                             | Isi pemetaan `pendingEthFees[poolId]` di callback swap V4 (`afterSwap`) dan alokasikan `buybackShare = (ethAvailable * config.buybackShareBps) / 10000` ke `buybackVault` sebelum membagikan sisa fee ke protokol.      | `pendingEthFees` tidak pernah ditambah di hook callback mana pun sehingga `sweepPoolFees` tidak melakukan apa-apa. Selain itu, formula bagi hasil membagi seluruh sisa fee ke `protocolFeeRecipient`, menghilangkan porsi buyback yang dijanjikan.                                                                                                             |
| **S11** ✅        | Medium            | Pengecualian Anti-Snipe Treasury Absen di BaseLaunchpadFactory (`BaseLaunchpadFactory._executeLaunchTokenV2`)                                    | Tambahkan `token.setRestrictionExempt(protocolFeeRecipient, true);` di `BaseLaunchpadFactory._executeLaunchTokenV2` segera setelah inisialisasi token.                                                                  | Berbeda dengan factory V2 lainnya, `BaseLaunchpadFactory` lupa mengecualikan `protocolFeeRecipient` dari pembatasan transfer.
